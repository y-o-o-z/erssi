The modern irssi, tuned for IRCnet.

erssi Shellter Edition keeps your nick, gathers your mentions, encrypts what you ask it to and updates itself from signed releases. No root needed.

$ curl -fsSL https://raw.githubusercontent.com/y-o-o-z/erssi/main/shellter-install.sh | sh

What an IRCnet user would otherwise script

Everything erssi brings stays: side panels, mouse support, 24-bit colour, image preview, a web frontend and irssi's Perl scripts. This edition adds the rest, and every command has a page in /help.

End-to-end encryption, built in

RPE2E natively, wire-compatible with repartee and its WeeChat and irssi scripts: XChaCha20-Poly1305 with per-sender keys, given only to people you accept. A message that cannot be read is never hidden. It protects what you say, not who talks to whom, and it has no forward secrecy.

Side panels that stay put

Your windows on the left and the channel's nicks by rank on the right. Saved layouts come back after a restart exactly as they were.

Your nick, kept

/keepnick takes it back the moment it is free: through MONITOR where the server offers it, otherwise ISON.

Mentions in one place

Private messages, notices from people and hilights in one window and a log, with a desktop notification through the terminal, also inside tmux.

One column for every line

The shellter theme puts messages, events and replies under one separator, in the colours of shellter.me; shellter-light for light terminals.

Search your logs

/search looks through the logs of a channel or every network in a separate process, so erssi carries on.

The full list: features.md.

Your session, also on the phone

erssi keeps running in tmux on your shell account. Reach the same session from a narrow ssh window or from a browser.

  • Readable on a narrow terminal. Long lines wrap and stay under the separator, even at 56 columns.
  • A web client when you need one. fe-web shares the session with a client such as NexusIRC; the web nick list follows the server.
  • Only you can open it. On a shared box fe-web listens on a Unix socket that only your account can reach.

Install in one line, update in two

Run it on your shell account. It goes to ~/.local/opt/erssi and keeps its settings in ~/.erssi, so it runs next to irssi.

1. Run the installer

It checks your system, the release's signature and the package before anything in your home changes.

curl -fsSL https://raw.githubusercontent.com/y-o-o-z/erssi/main/shellter-install.sh | sh

2. Start it inside tmux

The session survives logging out. The first start asks for a network, a nick and the theme, then connects.

tmux new -s irc erssi

3. Update when a release comes out

Then /upgrade in the running erssi keeps your windows; TLS connections reconnect once. An erssi installed for the whole system is updated by its administrator.

erssi --check-update
erssi --update

Debian 12 and 13, Ubuntu 24.04, FreeBSD 14 and 15, amd64

A ready-made binary, in seconds, installed only when the signature on its SHA256SUMS, its checksum and its manifest check out. The previous release stays for --rollback.

Other Linux and FreeBSD systems

Built from the newest signed release, with the test suite, in about two minutes. Needs GLib 2.70 or newer; missing packages are named for your administrator.

Every release can be checked

The installer carries the release key and the commit of every release, and installs nothing that does not match. You can check the same things by hand.

git -c gpg.program=false -c gpg.openpgp.program=false \
    -c gpg.x509.program=false -c gpg.format=ssh \
    -c gpg.ssh.allowedSignersFile=utils/allowed_signers \
    verify-tag shellter-v2026.11.3

Run it in a clone of the repository; gpg is switched off so that only the SSH key counts. It must report a good signature with the fingerprint on the right. Compare it with one you got another way, for example by asking on #shellter.

New in 2026.11.3

Released on 7 November 2026, the fixes of a security review of the code erssi adds to irssi. The rest of this list came with 2026.11.2, 2026.11.1 and 2026.11.0, from 1 to 3 November.

  • e2e

    /e2e decline holds. A declined peer can no longer undo it alone: a new key request, their next message, auto-accept or an autotrust rule no longer make them trusted again. Only /e2e accept, /e2e unrevoke or /e2e handshake do.

  • e2e

    Two erssi on one keyring. erssi saves the keyring only over the file it read. When another erssi wrote it in the meantime, the save is refused with a message and the other's change is kept, so a revocation or a new key is no longer lost.

  • web

    Web frontend logins. A login from a web page is paced like anyone else's, also from your own account.

  • images

    Image preview limits. At most 16 megapixels are decoded, so a small crafted PNG can no longer take half a gigabyte and freeze erssi.

  • upgrade

    /upgrade with a space in a path. A space in the path of erssi, its home or its config no longer makes /upgrade fail after the connections were let go.

  • backup

    Backups as root. --backup and --restore run as root no longer start the erssi of a prefix that may belong to another user.

  • disk

    The disk space warning in a hardened service. Under a seccomp filter that forbids the quota calls, as SystemCallFilter=@system-service of systemd does, 2026.11.1 was killed at its first look at the disk. erssi now checks the free space there and reads the quota only where it may.

  • backup

    Encrypted backups. erssi --backup --encrypt asks for a passphrase and writes a backup that only it opens, so it can sit where others might see it. erssi --restore knows it and asks for the passphrase.

  • disk

    A warning before the disk fills up. erssi says when little is left of the disk or your quota, before logs, keys and backups stop saving (/set disk_warn).

  • mouse

    The mouse on a slow link. A mouse report cut off on the way no longer eats what you type after it, and with the screen split the wheel scrolls the window under the pointer.

  • e2e

    Safe on a full quota. A message that needs a new key that cannot be saved is not sent but marked, and erssi --setup asks for SASL only when every server of the network is verified TLS.

  • update

    System installs stay the administrator’s. An erssi installed for the whole system is updated by its administrator: erssi --update and /update say so and never run an installer that is not yours.

  • update

    Update from inside erssi. /update install installs the newest signed release in the background while you chat, then says to load it with /upgrade. TLS connections reconnect once.
